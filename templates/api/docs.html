API reference

JSON over HTTP, base path /api/v1/. No third-party packages required.

Authentication

Create a token under Security & API, or exchange credentials (accounts without 2FA):

curl -X POST {{ SITE_URL }}/api/v1/auth/token/ \ -H "Content-Type: application/json" \ -d '{"username": "demo", "password": "Demo@12345"}'

Send it on every request: Authorization: Token vv_xxxxxxxx. Signed-in browser sessions may also call read-only (GET) endpoints.

Example

# list documents expiring soon, newest first curl -H "Authorization: Token $TOKEN" "{{ SITE_URL }}/api/v1/documents/?expiry=soon&sort=expiry" # upload curl -H "Authorization: Token $TOKEN" -F file=@passport.pdf -F title="Passport" -F category=identity \ -F tags="travel, id" {{ SITE_URL }}/api/v1/documents/ # update curl -X PATCH -H "Authorization: Token $TOKEN" -H "Content-Type: application/json" \ -d '{"expiry_date": "2031-05-01", "is_favorite": true}' {{ SITE_URL }}/api/v1/documents/12/ # verify a fingerprint publicly (no token) curl -X POST -H "Content-Type: application/json" -d '{"code": "VV-ABCD-EFGH-JKMN", "sha256": "…64 hex…"}' {{ SITE_URL }}/api/v1/verify/

Conventions

  • Pagination: ?page=2&page_size=25 (max 100). Responses include count, next, previous, results.
  • Filters on /documents/: q, category, folder, tag, status, favorite, expiry (expired|soon|valid|none), sensitivity, sort.
  • Errors: {"error": {"status": 400, "message": "…", "fields": {"title": ["…"]}}}.
  • Write requests (POST/PATCH/DELETE) require a token. PATCH bodies are JSON or form-encoded.
  • Critical documents cannot be downloaded through the API or shared by link.
